Sorting Sorting

A sorting algorithm visualizer for Windows that I designed, built, and released myself.

Get it on itch.io

Overview

Sorting Sorting turns sorting algorithms into something you can watch. Pick a method, from classics like Merge Sort and Quick Sort to oddballs like Bogo Sort and Pancake Sort, set how many bars you want, and see them swap, merge, and shuffle in real time. It times every run, so you can compare how long each algorithm takes.

I wanted it to be useful if you're curious about how algorithms work, and still be fun to watch if you're not. It's free to download, with pay-what-you-want pricing.

I was drawn to sorting algorithms when I was starting out and wanted to make fun games and apps. Two goals ended up sharing one project: I wanted to learn Love2D, and I wanted to learn the algorithms themselves, including what they're for and how their logic works. Building a visualizer was a way to do both, because I had to understand each algorithm well enough to show it.

I also wanted to show that engineering doesn't have to be serious all the time. If someone picks this up out of nowhere, I'd like them to learn that there are serious sorting algorithms and funny ones, and that code can be approachable.

Who it's for

Anyone. You don't have to care about algorithms. Maybe you just want to try it, or zone out to colorful bars.

Design decisions

Make each algorithm understandable

Watching bars move is satisfying, but it doesn't explain anything on its own. So the visualization carries a few cues:

  • Active bars light up in yellow, so you can see which values the algorithm is comparing or swapping right now.
  • Hover any algorithm for a plain-English description. Gnome Sort, for example, is explained as a gnome sorting flower pots.
  • Run history in the corner shows your latest, previous, and earlier timings, so comparing two algorithms doesn't need a stopwatch.
  • Sound is tied to the data: each bar's value maps to a pitch, so a sort has its own sound.

Plenty of controls without the overload

The hardest design problem was balance. There are 19 algorithms, a size from 2 to 500 bars, a speed control, auto sort, sound, and color options. Showing all of it at once would bury the one thing people came for: the bars.

So every control lives in a single side panel that can be tucked away, the stats stay as quiet text in the corner, and the bars get the rest of the screen. Less common settings, such as colors, go behind an Options screen instead of competing for attention.

Limits that guide instead of lock

Some algorithms can't take just any input. Bitonic Sort only works on powers of two, and Bogo Sort effectively never finishes on a large list. The easy answer is to disable controls. That would have made the app feel rigid and left people wondering why something was greyed out.

  • Bitonic Sort snaps your size to the nearest power of two, with a note explaining why, instead of refusing your input.
  • Bogo Sort suggests five items or fewer, but doesn't stop you from trying more.
  • Random skips those two, so it never picks an algorithm that needs special handling.

Humor on purpose

The lineup mixes the practical (Merge, Quick, Heap) with the absurd (Bogo, Stooge, Spaghetti, Sleep). The silly ones aren't filler. Showing how slow Bogo Sort really is teaches why efficient algorithms matter better than a lecture would.

A finished sort ends with a rainbow celebration, and Bogo Sort gets its own tune for pulling it off.

Build and release

Sorting Sorting is built in Lua with the Love2D framework. Each algorithm runs step by step so the screen can show every comparison and swap. Adding a new algorithm means adding one file and registering it, which keeps it easy to grow.

I released it on itch.io as pay-what-you-want, since I didn't make it to earn money. I'd rather inspire someone with something simple: coding and learning don't have to be hard, and they can be accessible. The page invites bug reports, feature ideas, and algorithm requests.

A note on process: I wrote the code myself, with help from an engineer friend on some sorting logic. When I got stuck, I used Claude Code to review logic and make quick, minor changes.

Reflection

To show an algorithm, I had to understand it, so building the visualizer was also how I learned them. The design lesson was restraint. With this many options, the work was deciding what to hide, what to explain, and what to quietly correct for people.
